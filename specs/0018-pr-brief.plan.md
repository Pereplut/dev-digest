1. **AC-60 (R61) is unimplementable as worded.** It asks that `PrIntentCard` and `BlastRadiusCard` "render their own error/empty state" when their endpoints are stubbed to fail. 2. **Nothing states what `PrBrief.intent` holds when no `pr_intent` row exists.** AC-16 (R18) requires generation to succeed anyway, and AC-57 (R58) requires the stored `json` to satisfy `PrBrief.parse()` — but `Intent` requires `{intent: string, in_scope: string[], out_of_scope: string[]}` (`server/src/vendor/shared/contracts/brief.ts:9-13`), all three present. Exactly one shape parses, so this is forced rather than ambiguous, but it is unstated. **Q2** confirms the placeholder and asks for a sentence in AC-16.
3. **On a reviewed PR the brief's `summary` renders twice.** AC-28 (R30) is unconditional ("WHEN a brief is present … render `summary` as visible text") while AC-39 (R46) also puts it in `VerdictBanner.summary`; AC-49 (R33) constrains only the *no-review* state.
